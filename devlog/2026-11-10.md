# Devlog: 2026-11-10

## Entry 1: Phase 1 step 1, task 5 done (agent loop + SQLite logging)

Built (commit 7c2e165):
- `agent/loop.py`: raw Anthropic SDK loop. Send task + tools, run any tools the model asks for, send results back (all in one user message), repeat until a final answer or the 10-step limit. Statuses: completed, step_limit, refused, truncated, error.
- `agent/registry.py`: dict of the five tools (description, input schema, function). `run_tool()` never raises; errors go back to the model as `Error: ...` text.
- `agent/pricing.py`: price table and per-request cost. Haiku 5.5 is $0.10/$0.50 per 1M tokens (higher rate if one prompt is over 100K tokens); Sonnet 5.5 is $2/$10. Prices were checked 2026-11-10 against a reference cached 2026-10-06, so **re-check before the final run**.
- `harness/logging_db.py`: SQLite `runs` table (task, status, final answer, steps, tokens, cost, model) and `tool_calls` table (step, tool, arguments JSON, result, is_error). Database path defaults to `runs/runs.db` (gitignored).
- `tests/test_loop.py`: 23 tests using a fake model (no real API calls).

Status: 86 tests passing. No real API call has been made yet.

### Decisions and notes
- **Security fix:** tools have a test-only `world` argument. `run_tool` now rejects any argument not declared in the tool's schema, so the model cannot repoint a tool at another folder. Tested on three tools.
- **Refusal fallbacks are off** on purpose. The API can re-run a refused request on another model, which would mix two models into one result. Refusals are logged as status `refused`.
- No thinking/effort settings are passed. Haiku 5.5 runs adaptive thinking at its default effort (medium). Revisit if results look odd.
- Failed runs log only the error type, never the error message (could contain sensitive text).
- Mistakes I made and fixed this session: two meaningless `or True` test assertions (removed) and one wrong price expectation in a test.
